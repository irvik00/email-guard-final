Локальный API

POST /api/analyze?mode=baseline|recall|review

Тело: исходные байты одного .eml, Content-Type: message/rfc822. По умолчанию baseline. Лимит 10 MiB проверяется при потоковом чтении. Имя файла, путь и модель передавать нельзя. Письмо не сохраняется.

curl.exe -X POST "http://127.0.0.1:8000/api/analyze?mode=baseline" -H "Content-Type: message/rfc822" --data-binary "@examples/app/demo_01.eml"

200: решение, insufficient_features или needs_review. 400: пустой/повреждённый файл. 413: больше 10 MiB. 415: неверный тип тела. 422: неверный режим/параметры. 429: занято. 503: необходимый компонент недоступен. Ошибка никогда не означает ham.

decision: 0 — обычное, 1 — спам, null — автоматического решения нет. components содержит отдельные оценки, пороги, T, статусы и усечение. ensemble_score всегда null. email содержит только ограниченные сведения и статические наблюдения; это не объяснения модели и не подтверждение фишинга.

GET /health — жив ли процесс. GET /ready?mode=baseline|recall|review — готовность выбранного режима и обоих компонентов. Readiness может быть 503 во время загрузки Laya, при этом baseline работает.

Схема OpenAPI. Документация полностью локальная, без CDN.
