# Обновление интерфейса и категорий

Это небольшой патч к email_guard_render из предыдущего шага. Новые веса, зависимости и обучение не добавлены. E0 и сохранённая Laya в исходном проекте не изменяются. На публичном Render по-прежнему доступен E0; Laya требует отдельного CUDA runtime и весов.

Изменения: фиолетовый/мятный/персиковый интерфейс, адаптивная страница, имя выбранного файла, карточки настоящих ответов, шкалы отдельных модельных оценок, детали ссылок/вложений/отписки, пояснения режимов, описание этапов обработки.

Добавлено email.category: пять тематических подсказок по ручным правилам RU/EN. Это не обученный классификатор и не новое экспериментальное качество. Категория не зависит от предсказанной метки spam/ham и не меняет её; уверенность не выдумывается. На UI указано «правила, не обученная модель». Несколько тем могут пересекаться; дополнительные совпадения показываются. Отсутствие совпадений → «Другое»; пустой текст → нет категории. Названия отправителей и признаки согласия на рассылку не восстанавливаются из ключевых слов.

Правила смотрят первые 5000 символов темы и первые 50000 символов текста. Это отдельное ограничение тематической подсказки, а не изменение входа E0. Веса, shared preprocessing, пороги, финальные метрики, протокол и словарь модели не менялись.

Проверки: 18 исходных app tests, 4 public deployment tests, 3 category tests (включая пять пользовательских примеров и сверку реального E0 с сохранёнными ответами на шести synthetic .eml). Дополнительные проверки UI/HTTP записаны в reports/deployment/ui_update_verification.json. Новая оценка качества спама или категорий на независимом наборе не проводилась. Категории не следует представлять в защите как обученную часть задания со звёздочкой.

Локальные проверки этой копии не удостоверяют успешную публикацию. Нужно дождаться Live на Render и выполнить smoke_public.py с настоящим HTTPS-адресом. Рабочий интерфейс Laya есть в коде, но новые Laya weights, CUDA Docker image и удалённый worker в этот патч не добавлены.

## Установить обновление

В том же PowerShell и каталоге, откуда запускали scripts/smoke_public.py. Здесь должен лежать Dockerfile. Не применять патч к большому исследовательскому проекту — только к отдельной папке публикации.

```powershell
Test-Path .\Dockerfile
Test-Path .\app\deployment_config.py
```

Оба значения должны быть True. Если раньше в файлы этой копии вручную вносились изменения, сначала сохранить их отдельной копией. Затем:

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\email_guard_ui_update.zip" -DestinationPath (Get-Location).Path -Force
py -3.12 .\scripts\verify_render_package.py
git status --short
git add .
git commit -m "Refresh Email Guard UI and add transparent topic hints"
git push
```

Integrity-проверка должна дать passed. В staged changes не должно быть моделей/датасетов/окружений. Патч обновляет release manifests: старые хеши не удостоверяют новую версию. На Render дождаться автоматической сборки, либо Manual Deploy → Deploy latest commit. Runtime, тариф Free и переменные окружения менять не нужно.

После Live обновить браузер Ctrl+F5 и выполнить:

```powershell
py -3.12 .\scripts\smoke_public.py --url https://email-guard-final.onrender.com --label render-ui
```

Ожидается passed, checks=20. Проверьте новую страницу, загрузку demo_02.eml и demo_04.eml; затем письмо со скидкой должно показать категорию «Реклама». Категории — отдельные подсказки; бинарное решение может быть любым реальным ответом E0.

Правильный URL начинается с https:// — с двумя слешами. https:/email-guard-final.onrender.com невалиден.
