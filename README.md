# Email Guard

**Анализ писем: спам, тема и детали, которые стоит проверить.**

Учебный ML-проект с веб-интерфейсом и API. Загрузите письмо в формате `.eml`, чтобы получить решение модели, тематическую подсказку и наблюдения о ссылках, отправителе и вложениях.

[Открыть демо](https://email-guard-final.onrender.com/) · [Документация API](https://email-guard-final.onrender.com/api-docs) · [Результаты и ограничения](MODEL_CARD.md)

**Python 3.12 · FastAPI · scikit-learn · TF-IDF · Logistic Regression · Laya · Docker**

---

## Возможности

- **Проверка спама.** Основная модель E0 анализирует тему и текст письма, показывает оценку и порог решения.
- **Тематические подсказки.** Реклама, предложения работы, финансовые сообщения, служебные уведомления и другое.
- **Разбор структуры.** Отправитель, ссылки, названия вложений, признаки отписки и предупреждения MIME-парсера.
- **Сравнение моделей.** При локально подключённой Laya доступны объединение решений и проверка их согласия.
- **Явный отказ.** Если признаков недостаточно или компонент недоступен, сервис сообщает об этом.

Приложение принимает одно письмо размером до **10 MiB**, обрабатывает его в памяти и не сохраняет загруженное содержимое. HTML и вложения не исполняются, переходы по ссылкам не выполняются.

> «Обычное письмо» — ответ спам-классификатора, а не гарантия безопасности. Подлинность отправителя, безопасность вложений и работоспособность отписки не подтверждаются. Тематические подсказки основаны на ручных правилах RU/EN; это отдельный слой, который не меняет решение о спаме.

## Демо и режимы

В [публичном демо](https://email-guard-final.onrender.com/) работает **E0 на CPU**. Режимы с Laya доступны в локальном запуске после подключения её весов и CUDA-окружения.

| Режим | Как принимает решение | Для чего нужен |
|---|---|---|
| **Основной** · `baseline` | Использует E0 | Проверка одной сохранённой моделью; режим по умолчанию |
| **Повысить обнаружение** · `recall` | Спам, если E0 **или** Laya определила спам | Снизить число пропусков ценой возможного роста ложных тревог |
| **Сверить модели** · `review` | Совпадение даёт общий ответ; разногласие требует ручной проверки | Выделить письма, по которым модели расходятся |

Объединённый ответ рассчитывается только при успешной работе необходимых компонентов. Их оценки показываются отдельно: единой «вероятности ансамбля» нет. Режим проверки согласия также может ошибаться, если ошибаются обе модели.

Для знакомства с приложением в [examples/app](examples/app/) есть **шесть вымышленных писем**. Для публичного показа используйте примеры без личных данных: при загрузке файл передаётся на сервер сайта.

## Быстрый запуск на Windows

Для основного режима нужны **Python 3.12 x64** и Git. Проверенная версия Python — 3.12.4. Веса E0 включены в репозиторий; видеокарта не требуется.

### 1. Скачать проект и установить зависимости

В PowerShell:

```powershell
git clone https://github.com/irvik00/email-guard-final.git
Set-Location .\email-guard-final

py -3.12 -m venv .venv-app
.\.venv-app\Scripts\python.exe -m pip install -r requirements-app.lock.txt
```

При установке пакетов нужен интернет. После установки основной режим работает с локальной моделью, без скачивания весов.

### 2. Запустить приложение

Из корня проекта:

```powershell
$env:PYTHONUTF8 = '1'
$env:EMAIL_GUARD_ARTIFACT_ROOT = (Resolve-Path .\artifacts).Path
.\.venv-app\Scripts\python.exe -m app.run --disable-laya
```

Откройте **http://127.0.0.1:8000/** и загрузите `.eml`. Остановка сервера — `Ctrl+C`.

Если порт занят, можно выбрать другой:

```powershell
.\.venv-app\Scripts\python.exe -m app.run --disable-laya --port 8001
```

### 3. Проверить готовность

В другом окне PowerShell:

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/ready"
```

Для запуска без Laya ожидаются `baseline: true`, `recall: false`, `review: false`.

## Локальное подключение Laya

**Laya — дополнительная нейросетевая модель.** В проекте используется сохранённая адаптированная версия `Laya_day5`. Её веса размером около 1,3 ГБ поставляются отдельно и не входят в публичный репозиторий.

Для подключения нужны:

1. Отдельный пакет `email_guard_laya_artifacts` с файлами из [MODEL_ARTIFACTS.md](MODEL_ARTIFACTS.md).
2. Окружение Python с совместимыми CUDA, PyTorch и версиями из [requirements-app-laya.lock.txt](requirements-app-laya.lock.txt).
3. Путь к Python этого окружения в `EMAIL_GUARD_LAYA_PYTHON`.

Если пакет с весами расположен рядом с корнем проекта, его можно добавить так:

```powershell
.\.venv-app\Scripts\python.exe scripts\prepare_model_artifacts.py --source ..\email_guard_laya_artifacts --destination artifacts --only-laya
```

Затем задайте путь к **подготовленному** окружению Laya и запустите приложение:

```powershell
$env:EMAIL_GUARD_ARTIFACT_ROOT = (Resolve-Path .\artifacts).Path
$env:EMAIL_GUARD_LAYA_PYTHON = 'C:\path\to\laya-env\Scripts\python.exe'
Remove-Item Env:EMAIL_GUARD_DISABLE_LAYA -ErrorAction SilentlyContinue
.\.venv-app\Scripts\python.exe -m app.run
```

Замените путь `C:\path\to\laya-env\Scripts\python.exe` на свой. Перед запуском остановите предыдущий сервер на этом порту.

Проверка готовности всех режимов:

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/ready?mode=review"
```

Laya загружается одним отдельным процессом; модель и токенизатор читаются локально. Если этот компонент недоступен, основной режим E0 продолжает работать. Проверенный вариант локального окружения — Windows с NVIDIA CUDA; перенос CUDA-окружения на другую машину отдельно не проверялся.

## Запуск через Docker

Docker-профиль включает **только E0 на CPU**. Нужны Docker Engine с Linux-контейнерами и Docker Compose.

Из корня проекта:

```powershell
docker compose build
docker compose up -d
Invoke-RestMethod "http://127.0.0.1:8000/ready"
```

Интерфейс: **http://127.0.0.1:8000/**. Остановка:

```powershell
docker compose down
```

Зависимости образа закреплены версиями и хешами; модель подключается только для чтения. Compose публикует порт на `127.0.0.1`. Подробности — в [deployment/README.md](deployment/README.md).

Локальный сценарий Docker Compose не проверялся на Windows-машине автора: Docker Engine и WSL на ней отсутствовали. Проверки приложения в Windows не подтверждают работу этого сценария.

## Как устроены модели

### E0 — основной классификатор

Тема и текст письма преобразуются в **символьные TF-IDF-признаки**: фрагменты длиной 3–5 символов. Затем **логистическая регрессия** выдаёт оценку спама.

E0 выбран по пятикратной кросс-валидации с учётом групп похожих писем. Сравнивались наивный Байес, логистическая регрессия со словными признаками и логистическая регрессия с символьными признаками. Словарь TF-IDF обучался внутри каждой обучающей части.

Рабочий порог **0.3037252359712881** выбран на отдельной валидационной выборке: максимизировалась F1 при наблюдаемой доле ложных срабатываний не выше 1%. Это условие отбора на конкретных данных, а не гарантия для будущей почты.

### Laya — дополнительный подход

Использован мультиязычный checkpoint `convaiinnovations/laya`. Выполнена адаптация классифицирующей части на размеченных данных — **300 шагов**, без изменения весов encoder. Для калибровки оценки и выбора порога использовались отдельные части обучающих данных.

Модель отвечает на фиксированный вопрос `Is this message unsolicited spam?`. Её вход ограничен первыми 700 токенами подготовленного текста. Точные параметры, пороги и идентификаторы файлов приведены в [карточке модели](MODEL_CARD.md) и [описании артефактов](MODEL_ARTIFACTS.md).

### Категории и наблюдения

Тематическая подсказка выбирается по ключевым словам на русском и английском. Её качество отдельно не оценивалось.

Отправитель, ссылки, имена вложений и признаки отписки показываются как **наблюдения парсера**. Они помогают просмотреть письмо, но не являются объяснением решения E0 и не подтверждают фишинг.

## Данные и результаты

Основные английские источники — **SpamAssassin** и **Ling-Spam**. После подготовки исторический набор разделён на **5 953 / 1 275 / 1 276** писем для обучения, валидации и тестирования. До разделения выполнялась группировка найденных точных и близких дубликатов.

Дополнительно использовались русскоязычный вспомогательный набор и небольшой личный набор для проверки ошибок при разработке. Тест преподавателя оценивался отдельно. Сырые корпуса и личная почта в репозиторий не включены; происхождение данных и условия использования описаны в [MODEL_CARD.md](MODEL_CARD.md).

| Набор | F1 E0 | Покрытие E0 | F1 Laya | Покрытие Laya |
|---|---:|---:|---:|---:|
| Исторический test | **0.9824** | 1 275 / 1 276 | 0.9722 | 1 276 / 1 276 |
| Тест преподавателя, полный | **0.9693** | 1 598 / 1 600 | 0.9401 | 1 598 / 1 600 |
| Тест преподавателя без найденных совпадений с train/validation | **0.9399** | 610 / 612 | 0.9017 | 610 / 612 |
| Русскоязычный вспомогательный test | 0.6730 | 3 410 / 5 990 | **0.8922** | 5 990 / 5 990 |

**Покрытие** — число писем с бинарным ответом относительно размера набора. F1 рассчитана только по этим ответам; отказы не считаются обычными письмами. При разном покрытии F1 относится к разным множествам примеров.

В тесте преподавателя обнаружены **988 из 1 600 писем**, совпадающих с историческими train/validation. Поэтому отдельно приведён разрез из 612 писем. Он также не полностью независим от прежних оценок: в teacher-наборе есть ещё 162 совпадения с историческим test.

Режим `recall` на полном тесте преподавателя уменьшил пропуски спама с **51 до 21**, увеличив ложные тревоги с **9 до 17**. Основным режимом остался заранее выбранный E0. Полные таблицы, включая ансамбли и долю ручной проверки, — в [FINAL_TABLES.md](reports/release/FINAL_TABLES.md).

**Границы применимости:** исторические английские письма не представляют современную почту; основной E0 ограниченно работает с русским. Русскоязычный вспомогательный набор не подтверждён как представительная выборка электронной почты. Сервис не реализует проверку SPF/DKIM/DMARC, антивирусный анализ вложений, подтверждённую классификацию фишинга, почтовую интеграцию или автоматическое дообучение.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка доступности приложения |
| `GET` | `/ready` | Готовность основного режима |
| `GET` | `/ready?mode=review` | Готовность режима с Laya |
| `POST` | `/api/analyze?mode=baseline` | Анализ одного письма |
| `GET` | `/api-docs` | Документация API |
| `GET` | `/openapi.json` | Схема OpenAPI |

Пример запроса из корня проекта:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/api/analyze?mode=baseline" -H "Content-Type: message/rfc822" --data-binary "@examples/app/demo_02.eml"
```

Тело запроса — содержимое `.eml`, без multipart-формы. Допустимые режимы: `baseline`, `recall`, `review`.

При нехватке признаков ответ содержит `insufficient_features`; при необходимости ручной проверки — `needs_review`. Недоступный компонент возвращает HTTP `503`, превышение лимита — `413`. Оценка модели не является гарантированной вероятностью для любого нового письма.
